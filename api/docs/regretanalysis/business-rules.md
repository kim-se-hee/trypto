# 복기 분석 공통 비즈니스 규칙

복기 리포트([regret-report.md](regret-report/index.md))와 복기 그래프([regret-chart.md](regret-chart/index.md))가 공통으로 참조하는 계산 규칙을 정의한다.

---

# 공통 용어

| 용어 | 의미 |
|------|------|
| `expected_amount` | 원칙을 지켰다면 거래했을 금액. "안 샀어야 했다"면 0, "이 시점에 팔았어야 했다"면 그때의 매도 금액 |
| `actual_amount` | 실제로 거래한 금액. 아직 보유 중이면 현재 평가 금액 |
| `loss_amount` | 원칙 위반이 만든 손익 차이. **양수면 손해**, 음수면 위반했지만 결과적으로 이득 |
| `기준가` | 위반 거래의 손익을 매길 때 비교 기준이 되는 가격. 결정 방법은 [기준가 결정 로직](#기준가-결정-로직) 참조 |

# 원칙별 손실 금액 계산

위반 유형에 따라 "원칙을 지켰다면" 시나리오의 금액을 산출한다. 모든 금액은 해당 거래소의 기축통화 단위(국내: KRW, 바이낸스: USDT)로 계산한다.

## 추격 매수 금지 (`CHASE_BUY_BAN`)

- **원칙 준수 시**: 해당 매수 주문을 하지 않았을 것
- **expected_amount**: 0 — 안 샀어야 하므로 투입 금액 없음
- **loss_amount**: 안 샀어야 할 코인을 산 뒤, 가격이 얼마나 빠졌는지(또는 올랐는지)

```
loss_amount = (체결가 - 기준가) × 체결수량

예) 1000원에 매수 → 이후 800원에 매도(기준가)
    loss_amount = (1000 - 800) × 수량 = 양수 → 손해

예) 1000원에 매수 → 이후 1200원에 매도(기준가)
    loss_amount = (1000 - 1200) × 수량 = 음수 → 위반했지만 이득
```

## 물타기 제한 (`AVERAGING_DOWN_LIMIT`)

- **원칙 준수 시**: 제한 횟수를 초과한 추가 매수를 하지 않았을 것
- **expected_amount**: 0 — 초과분은 안 샀어야 함
- **loss_amount**: 추격 매수 금지와 동일한 방식

```
loss_amount = (체결가 - 기준가) × 체결수량
```

## 과매매 제한 (`OVERTRADING_LIMIT`)

- **원칙 준수 시**: 제한 횟수를 초과한 주문을 하지 않았을 것
- **expected_amount**: 0 — 초과분은 거래하지 않았어야 함
- **loss_amount**: 초과 주문이 만든 손익. 매수와 매도의 계산 방향이 반대

```
매수 주문: loss_amount = (체결가 - 기준가) × 체결수량
매도 주문: loss_amount = (기준가 - 체결가) × 체결수량
```

- **매수 위반**: "안 샀어야 할 걸 샀다" → 위반분 우선 매칭으로 기준가를 결정한다 ([기준가 결정 로직](#기준가-결정-로직) 참조)
- **매도 위반**: "안 팔았어야 할 걸 팔았다" → 이미 판 거라 매칭할 게 없다. 기준가는 현재가를 사용한다

## 손절 미이행 (`LOSS_CUT`)

- **원칙 준수 시**: 손실률이 설정값에 도달했을 때 즉시 매도했을 것
- **expected_amount**: 손절 시점에 팔았다면 받았을 금액 = `평균 매수가 × (1 - 손절률/100) × 보유 수량`
- **actual_amount**: 실제 매도 금액. 아직 보유 중이면 현재 평가 금액

```
loss_amount = actual_amount - expected_amount

예) 손절 시점 매도가(expected) 90만원, 실제 매도가(actual) 70만원
    loss_amount = 70만 - 90만 = -20만 → 손절했으면 20만원 덜 잃었다
```

## 익절 미이행 (`PROFIT_TAKE`)

- **원칙 준수 시**: 수익률이 설정값에 도달했을 때 즉시 매도했을 것
- **expected_amount**: 익절 시점에 팔았다면 받았을 금액 = `평균 매수가 × (1 + 익절률/100) × 보유 수량`
- **actual_amount**: 실제 매도 금액. 아직 보유 중이면 현재 평가 금액

```
loss_amount = expected_amount - actual_amount

예) 익절 시점 매도가(expected) 130만원, 실제 매도가(actual) 110만원
    loss_amount = 130만 - 110만 = 20만 → 익절했으면 20만원 더 벌었다
```

# 기준가 결정 로직

`CHASE_BUY_BAN`, `AVERAGING_DOWN_LIMIT`, `OVERTRADING_LIMIT` (매수)의 수식에서 쓰이는 기준가를 정하는 방법.

## 위반분 우선 매칭

코인은 구분이 없으므로 어떤 코인이 매도되었는지 알 수 없다. 따라서 **위반 매수분이 먼저 매도된 것으로 간주한다.**

이 가정을 사용하는 이유:
- 코인은 하나하나 구분이 안 되므로, 어떤 순서로 매칭하든 "이게 진짜다"라고 할 근거가 없다. 그러니 우리 목적에 맞는 가정을 고르면 된다
- 위반분을 우선 매칭하면 매도가 발생할 때 위반의 영향이 바로 확정되어, "위반이 실제로 어떤 영향을 줬는가"를 빠르게 보여줄 수 있다

## 기준가 결정 절차

위반 매수 이후에 해당 코인의 매도 이력을 시간순으로 가져와서, 위반 매수 수량이 찰 때까지 매칭한다.

**1. 위반 수량이 전부 매칭된 경우 (전량 실현)**

매칭된 매도 체결가가 기준가가 된다. 값이 고정되므로 이후에는 변하지 않는다.

```
위반 매수: 20개 × 1000원
이후 매도: 50개 × 900원 → 위반 20개 전부 커버

loss_amount = (1000 - 900) × 20 = 2,000원 손해 (확정)
```

**2. 위반 수량이 일부만 매칭된 경우 (부분 실현)**

매칭된 부분은 매도 체결가로 확정, 남은 부분은 조회 시점의 현재가로 계산한다.

```
위반 매수: 20개 × 1000원
이후 매도: 10개 × 900원 → 위반 20개 중 10개 커버

실현분: (1000 - 900) × 10 = 1,000원 손해 (확정)
미실현분: (1000 - 현재가) × 10 (변동)
loss_amount = 실현분 + 미실현분
```

**3. 매도 이력이 없는 경우 (전량 미실현)**

조회 시점의 현재가를 기준가로 사용한다. 

```
위반 매수: 20개 × 1000원
매도 없음

loss_amount = (1000 - 현재가) × 20 (변동)
```

# 실현 손익의 배수 환산

위반 매수 수량 중 이후 매도와 짝지어진 몫이 실현분, 짝이 없어 아직 보유 중인 몫이 미실현분이다. 두 몫은 원칙 준수 했을 때의 자산에 반영하는 방법이 서로 다르다.

| 상태 | 금액의 성질 | 반영 방법 |
|------|--------|-------|
| 미실현분 | 배치마다 현재가로 재평가되어 시장에 따라 움직인다 | 따라서 금액을 그대로 더함 |
| 실현분 | 매도 시점 금액으로 확정된 뒤 변하지 않는다 | 실현일에 총자산 대비 비율(배수)로 환산해 두고, 이후의 자산에 곱함 |

## 실현분을 단순히 더하면 안 되는 이유

실현된 손익은 지갑에 섞여 이후 거래의 원금으로 사용된다. 따라서 그 몫은 이후 포트폴리오 수익률을 그대로 따라 오르내리는데, 확정 금액을 그대로 가산하면 발생 시점 값이 계속 사용되며 이 변동을 반영하지 못한다. 
포트폴리오가 하락하면 시장이 이미 가져간 금액을 한 번 더 빼는 이중 차감이 되고, 최악의 경우 준수 시 자산이 음수가 나올 수 있다. 
상승하면 반대로 위반으로 얻은 이득이 커지지 않아 위반 이득이 실제보다 작게 계산된다 (위반 이득 70만이 섞인 자산이 2배가 되면 빼야 할 몫은 140만인데, 박제된 70만만 뺀다).

미실현분에는 이 문제가 없다. 매일의 현재가 재평가가 "그 몫이 지금 얼마인가"를 이미 반영하고 있기 때문이다.

## 비례 가정

실현된 위반 손익은 잔고에 합쳐져 숫자 하나가 된다. 따라서 이후의 매수에 사용된 돈이 원래 내 돈인지 위반으로 번 돈인지는 구분할 수 없다. 
따라서 아래와 같이 가정한다.

> 실현된 위반 손익은 이후의 모든 거래에 자산 비율대로 정당한 자산과 함께 쓰였다.

## 배수 갱신

배수란 실현된 위반의 영향을 자산에서 걷어내는 비율이다. 
실제 자산에 미실현 위반 손실 합을 더한 값에 곱하면 원칙 준수 시 자산이 나온다 (미실현 위반이 없으면 실제 자산에 바로 곱한 값과 같다). 
위반 이득이 실현되면 1보다 작아지고(자산의 일부가 위반의 몫이므로), 위반 손해가 실현되면 1보다 커진다(준수 시 자산이 실제보다 크므로).
배수는 날마다 갱신된다. 
갱신에 필요한 값은 그날의 실현 손실 합계(R)·긴급 충전액(N)·총자산(A)이다. 
실현도 충전도 없는 날은 식에 0이 들어가 값이 변하지 않는다.

```
그날 갱신: 누적 배수 ← (누적 배수 × (A − N + R) + N) ÷ A

A = 그날 총자산 스냅샷, N = 그날 긴급 충전액, R = 그날 실현된 위반 손실 합계
```

- 실현도 충전도 없는 날(R=0, N=0): 값이 그대로다
- 실현만 있는 날(N=0): `누적 배수 × (1 + R/A)`로 줄어든다. 위반 손실은 양수가 손해이므로, 손해가 실현되면 배수가 커져 준수 시 자산이 실제 자산 위로 가고, 이득이 실현되면 작아져 아래로 간다
- 실현과 충전이 같은 날 겹쳐도 이 식 하나로 맞는다. 별도 규칙이 필요 없다
- 같은 날 여러 건의 위반 매매가 실현되면 원화로 환산해 합산해 R에 넣는다
- 총자산은 그날의 일별 자산 스냅샷을 사용한다(라운드 전체, 원화 환산). 정확히는 실현 순간의 자산을 써야 하지만 현재는 근사를 하며 오차를 허용한다
- 배수 값의 하한은 0이다. 자산이 음수가 되는 것을 방지하며, 근사 오차가 극단적으로 커지는 경우도 이 하한이 막는다

### 긴급 충전이 배수에 미치는 영향

긴급 충전은 위반과 무관한 새 돈이 들어오는 사건이다. 따라서 긴급 충전이 되면 배수가 1과 가까워진다.

**예시** : 1일차 자산 200 중 위반 실현 +100이라 누적 배수 1/2이고 2일차에 긴급 충전 200만을 한 경우

```
2일차 갱신: ((400 − 200) × 1/2 + 200) ÷ 400 = 3/4
준수 시 자산 = 400 × 3/4 = 300만
```

긴급 충전 시 배수를 갱신하지 않으면 위반 손익이 `400 × 1/2 = 200만`이 되어 충전한 돈까지 위반 몫으로 포함된다.

## 준수 시 자산 산출

```
그날의 원칙 준수 시 자산
  = (그날의 실제 자산 + 그날까지의 미실현 위반 손실 합) × 그날까지의 누적 배수

누적 배수 = 그날까지의 일별 갱신을 모두 반영한 값
```

미실현분을 먼저 가산한 뒤 배수를 곱한다. 실현분의 지분은 미실현 교정분을 포함한 자산 전체에 걸치기 때문이다.

실현일 당일에는 가산과 곱셈이 같은 값이다 — `자산 + 손실`과 `자산 × (1 + 손실/자산)`은 동일하다. 따라서 실현일을 경계로 곡선이 끊기지 않는다.

**예시** — 시드 100만 원 라운드

- 1일차: 위반 매수가 급등하여 매도로 +70만 원 확정(위반 손실 −70만 원). 자산 170만 원. 배수 = 1 − 70/170 = 100/170
- 2일차: 전액을 다른 코인에 매수했으나 −90% 폭락. 실제 자산 17만 원

| 계산 | 준수 시 자산 |
|------|-------------|
| 배수 환산 | 17만 × 100/170 = **10만 원** |
| 하루씩 재현한 실제 답 | 100만 × 0.1 = **10만 원** (일치) |
| 확정 금액 가산 (잘못된 방식) | 17만 − 70만 = −53만 원 (불가능한 값) |
