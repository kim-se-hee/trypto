## 목적

투자 라운드의 복기 그래프 데이터를 조회한다. 라운드 전체의 일별 자산 추이를 시각화하여 실제 투자 성과를 보여주고, "원칙을 지켰다면?" 시뮬레이션과 BTC 홀드 벤치마크를 겹쳐 단순 보유 대비 성과를 비교하게 하며, 위반 발생 시점을 그래프 위에 표시한다.

## 용어 정의

그래프는 라운드 단위로 조회하며, 모든 시리즈는 **원화(KRW)**다. 바이낸스(USDT) 몫은 고정 환율 **1 USDT = 1,400원**으로 환산해 합산한다.

1. **자산 추이 (Asset History)**: 일별 실제 자산(`actualAsset`), 규칙 준수 시 시뮬레이션 자산(`ruleFollowedAsset`), BTC 홀드 벤치마크(`btcHoldAsset`)
2. **위반 지점 마커 (Violation Markers)**: 위반 거래가 발생한 날짜와 해당 시점의 자산값

복기 분석 공통 용어(`expected_amount`, `actual_amount`, `loss_amount`, `기준가`)는 [../business-rules.md](../business-rules.md) 를 참조한다.

## 조회 항목

라운드에 대해 다음을 반환한다.

- 일별 자산 추이: 실제 자산(`actualAsset`), 규칙 준수 시 시뮬레이션 자산(`ruleFollowedAsset`, 분홍 점선), BTC 홀드 벤치마크(`btcHoldAsset`, 주황 실선)
- 위반 지점 마커(빨간 점): 위반이 발생한 날짜와 해당 시점의 자산값

## 조회 조건

- 해당 투자 라운드의 그래프 데이터를 조회한다
- 라운드 소유자만 조회할 수 있다 (본인 라운드 검증)
- 일별 자산 스냅샷이 아직 없으면 (라운드 시작 당일 등) 오류가 아니라 빈 그래프를 반환한다. 자산 추이와 위반 마커는 빈 목록, 총 일수는 0이다
- 복기 리포트가 아직 없으면 위반이 없는 것으로 간주한다. 시뮬레이션 자산은 실제 자산과 같고, 위반 마커는 표시되지 않는다

## 실제 자산 추이

라운드에 속한 모든 거래소의 일별 자산을 원화로 합산해 사용한다. 같은 날짜의 거래소별 자산을 합한 값이 그날의 실제 자산이다. 거래소 간 송금은 라운드 안에서의 자금 이동이므로 합산 값에 영향을 주지 않는다.

## 규칙 준수 시 시뮬레이션 자산 계산

위반이 없었다면의 가상 자산 추이를 일별로 계산한다.

```
ruleFollowedAsset[day] = actualAsset[day] + Σ(위반 손익 원화 환산액, 해당일까지 누적)
```

근사 계산이다. 완전한 포트폴리오 재시뮬레이션 대신 누적 손실 가산 방식을 사용한다. 실제로는 손실이 복리로 영향을 미치지만, 계산 복잡도 대비 직관적인 근사치를 제공한다. 특히 실현된 위반 손익이 실현 이후의 수익률 변동을 반영하지 못하는 한계가 있으며, 계산 모델 개선은 별도 과제([#326](https://github.com/kim-se-hee/trypto/issues/326))로 관리한다.

위반 거래의 위반 손익 자체를 산출하는 원칙별 계산 규칙과 기준가 결정 로직은 [../business-rules.md](../business-rules.md) 를 참조한다.

**계산 절차:**

1. 복기 리포트의 라운드 전체 위반 거래에서 위반 손익의 원화 환산액과 위반 발생 시각을 가져온다
2. 각 스냅샷 날짜에 대해, 해당일 이전(포함)에 발생한 위반 거래의 위반 손익을 누적 합산한다
3. `ruleFollowedAsset[day] = actualAsset[day] + cumulativeLoss[day]`

## BTC 홀드 벤치마크 계산

라운드에 투입된 외부 자금 전액으로 BTC만 매수하여 보유했을 때의 가상 자산 추이를 계산한다. 외부 자금은 **시드머니**와 **긴급 충전** 두 가지다. 거래소 간 송금은 라운드 안에서의 자금 이동이므로 벤치마크에 반영하지 않는다.

- **시드머니**: 첫 자산 스냅샷일의 BTC 종가로 전액 매수한 것으로 본다
- **긴급 충전**: 충전일의 BTC 종가로 충전 금액만큼 추가 매수한 것으로 본다. 첫 자산 스냅샷보다 앞선 충전은 시드머니와 함께 첫 스냅샷일에 매수한 것으로 본다

```
btcQuantity[day] = Σ(투입 금액 / 투입일의 BTC 종가), 투입일 ≤ day
btcHoldAsset[day] = btcQuantity[day] × 그날의 BTC 종가
```

- BTC 가격은 현금 유입 거래소(시드머니와 긴급 충전이 지급되는 국내 거래소)의 KRW 마켓 일별 종가를 사용한다. 시드머니와 충전 금액이 모두 원화이므로 환산이 필요 없다
- 수수료는 적용하지 않는다 (벤치마크 비교 목적)

**계산 절차:**

1. 라운드의 시드머니와 긴급 충전 내역(충전일·금액)을 조회한다
2. 투입 건마다 `투입 금액 / 투입일의 BTC 종가`로 매수 수량을 구해 누적한다
3. 각 스냅샷 날짜의 BTC 종가를 조회하여 `btcHoldAsset`을 계산한다

**BTC 가격 데이터 소스:**
- 저장된 BTC 시세 이력에서 일별 종가를 조회한다

## 위반 마커 생성

복기 리포트의 위반 거래 목록을 기반으로 그래프 위 마커 데이터를 생성한다.

1. 라운드 전체 위반 거래에서 위반 발생 시각의 날짜를 스냅샷 날짜에 매핑한다
2. 해당 스냅샷 날짜의 실제 자산(라운드 합산)을 마커의 자산값으로 설정한다
3. 같은 날짜에 여러 위반이 있으면 **날짜당 하나로 합친다**. 거래소가 달라도 같은 날짜면 하나의 마커다. 세부 내용은 리포트 API의 위반 거래 목록에서 확인한다

## 규칙 토글 시뮬레이션

사용자는 원칙을 골라 켜고 끄면서 "이 원칙만 지켰다면 자산이 어떻게 흘렀을까"를 확인한다.

- 서버는 전체 원칙을 준수했을 때의 시뮬레이션 자산만 제공한다. 원칙 조합별 자산은 미리 계산하지 않는다. 조합의 수가 많은 반면, 계산에 필요한 재료는 복기 리포트에 이미 모두 들어 있기 때문이다
- 클라이언트는 복기 리포트의 위반 거래 목록에서 켜 둔 원칙 몫의 위반 손익 **원화 환산액**만 골라 발생일 순으로 누적하고, 이를 그날의 실제 자산에 더한다. 서버가 전체 원칙 곡선을 만드는 방식과 같은 계산이다
- 위반이 없는 날은 직전 누적값을 그대로 유지한다. 따라서 곡선은 위반이 발생한 날에만 꺾인다
- 위반 손익은 음수일 수 있다. 원칙을 어긴 쪽이 결과적으로 이득이었던 경우이며, 이때 곡선은 그 시점에 실제 자산 아래로 내려간다
- 그래프가 다루는 기간보다 앞서 발생한 위반이 있다면 첫날의 누적값에 포함한다

**곡선이 만족해야 할 조건**

- 원칙을 모두 끄면 실제 자산 곡선과 완전히 겹친다
- 원칙을 모두 켜면 서버가 제공하는 전체 원칙 준수 곡선과 모든 지점에서 일치한다
- 원칙을 하나만 켜면 그 원칙의 위반 발생일에만 꺾이고, 꺾인 높이의 합은 리포트의 해당 원칙 총 위반 손익(원화 환산)과 같다
- 원칙을 모두 켠 곡선의 마지막 지점은 리포트 요약의 원칙 준수 시 자산과 항상 일치한다. 요약의 위반 손익 합계가 음수 보정 없이 곡선과 같은 값을 쓰기 때문이다
